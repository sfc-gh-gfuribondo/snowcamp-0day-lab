    Core Concepts

    There are only five ideas you need to start. Everything else builds on them.

    1. Storage and compute are separate

    Your data sits in storage, and you pay a small monthly amount for how much of it you keep. Queries run on compute, and you pay only while it's running. Because the two are separate, the finance team and the data science team can each have their own compute working on the same data without slowing each other down.

    2. A virtual warehouse is your compute engine

    • It does not store data. Think of it as the engine, not the gas tank.
    • Sizes go from XSMALL up to 6XLARGE. Each size up is about twice as fast and twice the cost per hour.
    • Auto-suspend pauses it when it's idle, so it stops using credits. Auto-resume starts it again when you run a query.
    • Compute is billed in credits, by the second. An XSMALL warehouse uses 1 credit per hour of running time.

    3. Data is organized like folders

    Account
 └── Database        DAY0_LAB
      └── Schema     HEALTHCARE
           ├── Table   PATIENTS
           ├── Table   ENCOUNTERS
           └── View    ENCOUNTER_SUMMARY

    Every object has a full name made of all three parts: DAY0_LAB.HEALTHCARE.PATIENTS.

    4. Roles decide what you can do

    You never get permissions directly. Permissions are given to roles, and roles are given to you. You use one role at a time, and you can see which one in the bottom-left corner of the screen.

    RoleThink of it as
    ACCOUNTADMINThe master key. Billing and account settings. Use it sparingly.
    SYSADMINBuilds things: warehouses, databases and tables. We'll use this one.
    USERADMIN / SECURITYADMINManages users and who gets which role.
    PUBLICEveryone has it. It can do very little.

    5. Context: role, warehouse, database, schema

    Every SQL file you open in a Workspace has a current role, warehouse, database and schema. Setting them with USE ... lets you write PATIENTS instead of DAY0_LAB.HEALTHCARE.PATIENTS.

    Try it: see your context

    Open a new SQL file in your Workspace (Projects › Workspaces › + Add new › SQL File), paste this, and run it:

    SELECT CURRENT_USER(), CURRENT_ROLE(), CURRENT_WAREHOUSE(), CURRENT_DATABASE();

SHOW WAREHOUSES;
SHOW ROLES;

    The first query tells you who you are and what you're using. CURRENT_DATABASE() is probably empty because you haven't chosen one yet. SHOW commands list objects. Notice the size and auto_suspend columns in the warehouse list.

    Try itRun the first query again. Then click the role and warehouse selector above the editor, switch to SYSADMIN, and run it once more. The results change with your context.

    Set Up and Load Data

    Open a SQL file in your Workspace

    1. Go to Projects › Workspaces. This is your personal workspace, a cloud folder where your SQL files, Python scripts, and notebooks live. Click + Add new › SQL File (in older versions of Snowsight this was called + Worksheet).
    2. Paste the SQL below. To run all of it, press Ctrl+Shift+Enter (Windows) or Cmd+Shift+Enter (Mac), or use the dropdown next to the Run button and choose Run All. To run a single statement, put your cursor in it and press Ctrl/Cmd+Enter.
    USE ROLE SYSADMIN;

-- 1. A small compute engine that pauses itself after 60 idle seconds
CREATE WAREHOUSE IF NOT EXISTS LAB_WH
  WAREHOUSE_SIZE = 'XSMALL'
  AUTO_SUSPEND = 60
  AUTO_RESUME = TRUE
  INITIALLY_SUSPENDED = TRUE;

-- 2. A database and schema (the "folders")
CREATE DATABASE IF NOT EXISTS DAY0_LAB;
CREATE SCHEMA IF NOT EXISTS DAY0_LAB.HEALTHCARE;

USE WAREHOUSE LAB_WH;
USE SCHEMA DAY0_LAB.HEALTHCARE;

-- 3. Three empty tables, ready for the CSV files
CREATE OR REPLACE TABLE PATIENTS (
  PATIENT_ID VARCHAR, FIRST_NAME VARCHAR, LAST_NAME VARCHAR, BIRTHDATE DATE,
  GENDER VARCHAR, RACE VARCHAR, CITY VARCHAR, COUNTY VARCHAR, STATE VARCHAR,
  INCOME NUMBER(10,0), PAYER VARCHAR, PRIMARY_CONDITION VARCHAR
);

CREATE OR REPLACE TABLE ENCOUNTERS (
  ENCOUNTER_ID VARCHAR, PATIENT_ID VARCHAR, START_TS TIMESTAMP_NTZ, STOP_TS TIMESTAMP_NTZ,
  ENCOUNTER_CLASS VARCHAR, DESCRIPTION VARCHAR, TOTAL_COST NUMBER(12,2), PAYER_COVERAGE NUMBER(12,2)
);

CREATE OR REPLACE TABLE CLINICAL_NOTES (
  NOTE_ID VARCHAR, PATIENT_ID VARCHAR, ENCOUNTER_ID VARCHAR,
  NOTE_DATE DATE, NOTE_TYPE VARCHAR, NOTE_TEXT VARCHAR
);
    What just happened?You built a compute engine (LAB_WH), a place to keep data (DAY0_LAB.HEALTHCARE), and three empty tables. This is the same as Part A of setup.sql.

    SQL Basics

    SQL is how you ask a database questions. Run each query and look at the results before moving to the next one.

    1. Look at some rows

    SELECT * FROM PATIENTS LIMIT 10;

    * means "every column". LIMIT keeps the result small. Use it whenever you're exploring a table.

    2. Filter and sort

    SELECT FIRST_NAME, LAST_NAME, CITY, PAYER
FROM PATIENTS
WHERE CITY = 'Boston'
  AND PAYER = 'Medicare'
ORDER BY LAST_NAME;
    Watch outText inside quotes is case-sensitive: 'boston' won't match 'Boston'. Column and table names are not case-sensitive.

    3. Count and total with GROUP BY

    SELECT ENCOUNTER_CLASS,
       COUNT(*)                  AS encounters,
       ROUND(AVG(TOTAL_COST), 2) AS avg_cost,
       SUM(TOTAL_COST)           AS total_cost
FROM ENCOUNTERS
GROUP BY ENCOUNTER_CLASS
ORDER BY total_cost DESC;

    Which kind of visit costs the most in total? Inpatient visits are rare but expensive.

    Make a chartAbove the results, click Chart. Snowsight builds a bar chart for you. Try setting ENCOUNTER_CLASS on the X-axis and TOTAL_COST as the bars.

    4. Combine tables with JOIN

    Encounters only store a PATIENT_ID. To see costs by city or insurer, you join to PATIENTS:

    SELECT p.PAYER,
       COUNT(*)                                  AS encounters,
       SUM(e.TOTAL_COST)                         AS total_cost,
       SUM(e.TOTAL_COST - e.PAYER_COVERAGE)      AS patient_out_of_pocket
FROM ENCOUNTERS e
JOIN PATIENTS p ON p.PATIENT_ID = e.PATIENT_ID
GROUP BY p.PAYER
ORDER BY patient_out_of_pocket DESC;

    e and p are short nicknames (aliases) for the tables.

    5. Work with dates

    SELECT DATE_TRUNC('month', START_TS) AS month,
       COUNT(*)                     AS encounters
FROM ENCOUNTERS
WHERE ENCOUNTER_CLASS = 'emergency'
GROUP BY month
ORDER BY month;

    Switch to Chart and pick Line to see emergency visits over time.

    6. Save a query as a view

    A view is a saved query that behaves like a table. Your Streamlit app in Module 6 will read from this one.

    CREATE OR REPLACE VIEW ENCOUNTER_SUMMARY AS
SELECT e.ENCOUNTER_ID,
       e.PATIENT_ID,
       p.CITY,
       p.PAYER,
       DATEDIFF('year', p.BIRTHDATE, e.START_TS) AS AGE_AT_VISIT,
       e.ENCOUNTER_CLASS,
       e.START_TS::DATE                          AS VISIT_DATE,
       e.TOTAL_COST,
       e.PAYER_COVERAGE,
       e.TOTAL_COST - e.PAYER_COVERAGE           AS OUT_OF_POCKET
FROM ENCOUNTERS e
JOIN PATIENTS p ON p.PATIENT_ID = e.PATIENT_ID;

SELECT * FROM ENCOUNTER_SUMMARY LIMIT 10;

    Go to Monitoring › Query History and click one of your queries. Open the Query Profile tab to see each step Snowflake took and how long it took. When a query is slow, this is the first place to look.

    SQL Challenges

    Now it's your turn. Try each question on your own first, then click Show answer to compare. There's usually more than one correct way to write it.

    1. How many patients are in each city?

    Hint: GROUP BY, like the encounter query in Module 4.

    Show answer 
    SELECT CITY, COUNT(*) AS patients
FROM PATIENTS
GROUP BY CITY
ORDER BY patients DESC;

    2. Which 5 patients had the most emergency visits?

    Hint: join ENCOUNTERS to PATIENTS, filter with WHERE, and finish with LIMIT 5.

    Show answer 
    SELECT p.FIRST_NAME, p.LAST_NAME, COUNT(*) AS er_visits
FROM ENCOUNTERS e
JOIN PATIENTS p ON p.PATIENT_ID = e.PATIENT_ID
WHERE e.ENCOUNTER_CLASS = 'emergency'
GROUP BY p.FIRST_NAME, p.LAST_NAME
ORDER BY er_visits DESC
LIMIT 5;

    3. What is the average cost per visit for each primary condition?

    Hint: PRIMARY_CONDITION is on PATIENTS, and costs are on ENCOUNTERS.

    Show answer 
    SELECT p.PRIMARY_CONDITION,
       COUNT(*)                    AS encounters,
       ROUND(AVG(e.TOTAL_COST), 2) AS avg_cost
FROM ENCOUNTERS e
JOIN PATIENTS p ON p.PATIENT_ID = e.PATIENT_ID
GROUP BY p.PRIMARY_CONDITION
ORDER BY avg_cost DESC;

    4. Which payers cover patients aged 65 and over?

    Hint: the ENCOUNTER_SUMMARY view already has an AGE_AT_VISIT column. To count unique patients, use COUNT(DISTINCT ...).

    Show answer 
    SELECT PAYER, COUNT(DISTINCT PATIENT_ID) AS patients_65_plus
FROM ENCOUNTER_SUMMARY
WHERE AGE_AT_VISIT >= 65
GROUP BY PAYER
ORDER BY patients_65_plus DESC;

    5. How many clinical notes mention "shortness of breath"?

    Hint: ILIKE searches text without caring about upper or lower case. % means "anything".

    Show answer 
    SELECT COUNT(*) AS notes
FROM CLINICAL_NOTES
WHERE NOTE_TEXT ILIKE '%shortness of breath%';
    Why this mattersChallenge 5 searches for exact words. In the Cortex AI Lab, Cortex Search finds notes by meaning instead, so a search for "trouble breathing" also finds "shortness of breath".

    Time Travel: Undo Your Mistakes

    Snowflake keeps earlier versions of your data. By default it keeps 1 day of history, and up to 90 days on Enterprise. You can query the past, restore it, and even bring back dropped tables.

    1. Make a mistake on purpose

    -- Remember the time before the mistake
SET before_mistake = CURRENT_TIMESTAMP();

-- Oops: forgot the WHERE clause, so every patient now lives in Boston
UPDATE PATIENTS SET CITY = 'Boston';

SELECT CITY, COUNT(*) FROM PATIENTS GROUP BY CITY;

    Only one row comes back: all 500 patients are now in Boston.

    2. Look at the past

    SELECT CITY, COUNT(*)
FROM PATIENTS AT(TIMESTAMP => $before_mistake)
GROUP BY CITY;

    All ten cities are back. AT(...) asks for the table as it was at that moment.

    3. Restore it

    INSERT OVERWRITE INTO PATIENTS
SELECT * FROM PATIENTS AT(TIMESTAMP => $before_mistake);

SELECT CITY, COUNT(*) FROM PATIENTS GROUP BY CITY;

    4. Bring back a dropped table

    DROP TABLE CLINICAL_NOTES;
SELECT COUNT(*) FROM CLINICAL_NOTES;   -- error: does not exist

UNDROP TABLE CLINICAL_NOTES;
SELECT COUNT(*) FROM CLINICAL_NOTES;   -- 1,500 again

    Bonus: zero-copy clone

    CREATE TABLE PATIENTS_SANDBOX CLONE PATIENTS;

    A clone is a full, editable copy that's ready instantly and uses no extra storage until you change it. It's useful for testing changes safely. You can clone whole schemas or databases too.

    If you see this error "Session variable '$BEFORE_MISTAKE' does not exist": session variables only last while your current SQL file session is open. Run the SET line again, then repeat the steps.

    Your First Streamlit App

    Streamlit turns a short Python script into an interactive web app. In Snowflake, the app runs right next to your data, so there are no servers, passwords or files to move.

    1. Create the app

    1. Go to Projects › Streamlit and click + Streamlit App.
    2. For the app title, enter Encounter Explorer.
    3. For location, choose database DAY0_LAB and schema HEALTHCARE.
    4. For the warehouse, choose LAB_WH. If you're asked for a runtime, keep the default.
    5. Click Create. A sample app opens, with code on the left and the running app on the right.

    2. Replace the code

    Select all of the sample code, delete it, paste the code below, and click Run.

    import streamlit as st
from snowflake.snowpark.context import get_active_session

st.title("Encounter Explorer")
st.caption("Built on DAY0_LAB.HEALTHCARE.ENCOUNTER_SUMMARY")

session = get_active_session()  # already logged in - no password needed

# Load the view you created in Module 4 into a pandas DataFrame.
df = session.table("DAY0_LAB.HEALTHCARE.ENCOUNTER_SUMMARY").to_pandas()

# Sidebar filters
cities = st.sidebar.multiselect("City", sorted(df["CITY"].unique()))
payers = st.sidebar.multiselect("Payer", sorted(df["PAYER"].unique()))
if cities:
    df = df[df["CITY"].isin(cities)]
if payers:
    df = df[df["PAYER"].isin(payers)]

# Headline numbers
c1, c2, c3 = st.columns(3)
c1.metric("Encounters", f"{len(df):,}")
c2.metric("Patients", f"{df['PATIENT_ID'].nunique():,}")
c3.metric("Total cost", f"${df['TOTAL_COST'].sum():,.0f}")

st.subheader("Total cost by encounter class")
st.bar_chart(df.groupby("ENCOUNTER_CLASS")["TOTAL_COST"].sum())

st.subheader("Most expensive encounters")
st.dataframe(df.sort_values("TOTAL_COST", ascending=False).head(20), use_container_width=True)

    3. Play with it

    • Pick a city or two in the sidebar. The numbers and the chart update right away.
    • Try a change yourself: replace "ENCOUNTER_CLASS" in the bar_chart line with "PAYER", then click Run.

    4. Add a clinical notes search

    Paste this at the bottom of your code and click Run:

    st.subheader("Search clinical notes")
term = st.text_input("Find notes containing", "shortness of breath")
if term:
    notes = session.sql(
        """SELECT NOTE_DATE, PATIENT_ID, NOTE_TEXT
           FROM DAY0_LAB.HEALTHCARE.CLINICAL_NOTES
           WHERE NOTE_TEXT ILIKE ?
           ORDER BY NOTE_DATE DESC
           LIMIT 50""",
        params=[f"%{term}%"],
    ).to_pandas()
    st.write(f"{len(notes)} notes found (showing up to 50)")
    st.dataframe(notes, use_container_width=True)

    Type different words, such as fatigue or refer to specialist. Each time you type, Streamlit runs your script again with the new value.

    Good habitThe ? and params= pass the user's text to Snowflake as a value, not as part of the SQL. That stops someone from typing something that changes your query. Never paste user input straight into a SQL string.
    How this worksget_active_session() uses the role and warehouse you're already signed in with, so the app can only see data your role is allowed to see. Snowflake's normal security rules apply to the app too.
    If you see this error "Object 'ENCOUNTER_SUMMARY' does not exist or not authorized": go back to Module 4, step 6, and create the view. Also check that the app's location is DAY0_LAB.HEALTHCARE.

    Roles and Access

    The care team should see the encounter summary, but not patient names or birthdates. You'll create a role that can do exactly that and nothing more.

    1. Create the role and give it to yourself

    USE ROLE USERADMIN;              -- the role that manages roles
CREATE ROLE IF NOT EXISTS CARE_TEAM;

SET me = CURRENT_USER();
GRANT ROLE CARE_TEAM TO USER IDENTIFIER($me);
GRANT ROLE CARE_TEAM TO ROLE SYSADMIN;   -- best practice: admins inherit custom roles

    2. Grant only what's needed

    USE ROLE SYSADMIN;               -- the owner of the warehouse, database and view

GRANT USAGE  ON WAREHOUSE LAB_WH                        TO ROLE CARE_TEAM;
GRANT USAGE  ON DATABASE  DAY0_LAB                      TO ROLE CARE_TEAM;
GRANT USAGE  ON SCHEMA    DAY0_LAB.HEALTHCARE           TO ROLE CARE_TEAM;
GRANT SELECT ON VIEW      DAY0_LAB.HEALTHCARE.ENCOUNTER_SUMMARY TO ROLE CARE_TEAM;
    Why so many grants?To read a view, a role needs access at every level: the warehouse to run the query, plus the database, the schema and the view itself. The role has no grant on the PATIENTS table. The view only shows city and payer, so names and birthdates stay hidden.

    3. Test it as the care team

    USE ROLE CARE_TEAM;
USE WAREHOUSE LAB_WH;

SELECT * FROM DAY0_LAB.HEALTHCARE.ENCOUNTER_SUMMARY LIMIT 5;   -- works

SELECT * FROM DAY0_LAB.HEALTHCARE.PATIENTS LIMIT 5;            -- fails

UPDATE DAY0_LAB.HEALTHCARE.ENCOUNTER_SUMMARY SET PAYER = 'x';  -- fails: read-only

    The second and third statements fail with "does not exist or not authorized". Snowflake won't even confirm that a table exists if your role can't see it.

    4. Share your app

    1. Switch back by running USE ROLE SYSADMIN;.
    2. Open your Encounter Explorer app and click Share (top right).
    3. Add the role CARE_TEAM, then copy the app link.
    Good to knowA Streamlit app runs with its owner's permissions, which here is SYSADMIN. Anyone you share it with sees what the app shows, even if their role can't read the tables directly. So decide what the app displays before you share it. This app reads the patient-free view and the notes table, so think about whether the notes search should be part of a shared app.
    USE ROLE SYSADMIN;   -- switch back before you continue
